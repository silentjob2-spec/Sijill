# نظام إدارة الطلاب - V27

## الجديد في V27 (الصور وعدم تكرارها على Drive)

- إزالة مخطط «توزيع الحالات حسب نوع السلوك» من تقرير السلوك لتوفير مساحة، واختصار شريحة الفلاتر الطويلة.
- **إصلاح تكرار الصور على Drive:** رفع واحد فقط لكل صورة (حتى لو تزامنت المزامنة مع الحفظ)، وعدم إعادة رفع الصور المسترجعة من Drive، وحذف الملف القديم عند استبدال الصورة أو إزالتها أو حذف الحالة/الطالب/تصفير البيانات.
- لم يعد الموقع يحمّل كل الصور من Drive إلى المتصفح عند الفتح (توفير مساحة وسرعة)؛ تُجلب الصورة فقط إذا تعذّر عرضها.
- **مهم:** حدّث `Code.gs` ثم Deploy > Manage deployments > Edit > New version (نفس الرابط).
- لتنظيف التكرارات القديمة: من محرر Apps Script شغّل `previewUnusedImages()` لمعاينة الملفات غير المستخدمة، ثم `trashUnusedImages()` لنقلها إلى سلة المهملات (قابلة للاسترجاع 30 يومًا).

# نظام إدارة الطلاب - V17

## الجديد في V17

- **رابط Google Apps Script مثبّت** داخل الموقع ولا يتغيّر (يظهر للقراءة فقط في صفحة Google Sheets).
- **المزامنة التلقائية الآمنة:** لا ترفع الصفحة بياناتها تلقائيًا إلا بعد أول «استرداد» أو «رفع» يدوي من هذا المتصفح، حتى لا يمسح متصفح جديد فارغ بيانات الجدول.
- **إصلاح ظهور التاريخ 1899-12-30 مكان الوقت:** كان سببه أن Google Sheets يحوّل «08:19» إلى قيمة وقت. عُدّل `Code.gs` لتثبيت أعمدة الوقت/التاريخ كنص ولقراءة الوقت بصيغة HH:mm. **يجب نشر نسخة جديدة من السكربت** (Deploy > Manage deployments > تعديل > New version) ثم الضغط على «استرداد من Sheets».
- **توسيع المسافات في نموذج السلوك** ومحاذاة حقلي التاريخ والوقت وباقي الحقول.

# نظام إدارة الطلاب - V14

## الجديد في هذا الإصدار (تحديث حسب ملاحظاتكم)

- **قائمة كاملة للسلوكيات في تقرير السلوك:** بدل خانة البحث الحر، أصبح حقل «نوع السلوك» في تقرير السلوك قائمة منسدلة تعرض كل السلوكيات الموجودة في النظام فورًا عند الفتح (مع خانة بحث فوقها لو كانت القائمة طويلة)، فتختار سلوكًا محددًا بدقة بدل الكتابة.
- **الوقت يتحدّث تلقائيًا:** حقل «الوقت» في شاشة تسجيل السلوك يبقى محدَّثًا مع الوقت الحالي تلقائيًا كل بضع ثوانٍ طالما لم تُعدّله يدويًا ولم تكن تعدّل حالة قديمة أو تاريخًا غير اليوم؛ بمجرد ما تلمسه بنفسك يتوقف عن التحديث التلقائي حتى تحفظ الحالة التالية.
- **تصميم أجمل لإرفاق الصورة:** استبدلنا زر اختيار الملف الافتراضي (القبيح) بزر منسّق بنفس شكل باقي أزرار الموقع، مع اسم الصورة المختارة ظاهر بجانبه، ومعاينة أكبر وأوضح للصورة داخل بطاقة أنيقة، وبنقرة على الصورة تكبر في نافذة عرض.

## التشغيل على GitHub Pages

هذا المشروع تطبيق ويب ثابت (HTML/CSS/JavaScript) ولا يحتاج إلى Node.js أو PHP أو خادم قاعدة بيانات حتى يعمل.

1. ارفع الملفات إلى مستودع GitHub.
2. من Settings > Pages اختر النشر من الفرع الرئيسي ومجلد `/root`.
3. افتح رابط GitHub Pages.

## حفظ البيانات

- البيانات أثناء الاستخدام تحفظ في `localStorage` داخل المتصفح.
- `database.json` هو ملف بيانات ابتدائي يتم تحميله عند أول تشغيل إذا لم توجد بيانات محفوظة في المتصفح.
- GitHub Pages لا يستطيع JavaScript من المتصفح الكتابة مباشرة إلى `database.json` داخل المستودع.
- لن تكون البيانات مشتركة تلقائيًا بين أجهزة مختلفة.
- لنقل البيانات بين جهازين استخدم النسخ الاحتياطي والاسترداد داخل الموقع.

## تقرير الحضور والغياب

- لكل طالب سجل واحد فقط لكل يوم.
- لا يمكن أن يكون الطالب حاضرًا وغائبًا في اليوم نفسه.
- عند تغيير الحالة في اليوم نفسه يتم تعديل السجل بدل إنشاء سجل ثانٍ.
- يتم تنظيف السجلات المكررة القديمة تلقائيًا واعتماد آخر حالة محفوظة.
- التقرير يعرض لكل طالب عدد أيام الحضور والغياب وأيام الغياب بالتحديد.
- ملخص التقرير لا يجمع الحضور لكل الطلاب على أنه عدد أيام عامة؛ بل يعرض عدد أيام الدراسة المسجلة، ثم إجمالي سجلات الحضور والغياب بعبارة واضحة.
